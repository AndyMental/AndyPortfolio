# Render Deployment

This app is configured for Render with `render.yaml`.

## Host Choice

Render is the chosen host for this slice because it supports Rails and managed
Postgres directly from a blueprint. Fly.io remains a viable Docker-based option,
but it would add container and database app management that this small Rails app
does not need yet.

## Required Environment Variables

The Render blueprint declares these values:

- `DATABASE_URL`: provided by the `andyportfolio-db` Render Postgres database.
- `RAILS_ENV=production`
- `RAILS_LOG_TO_STDOUT=1`
- `RAILS_SERVE_STATIC_FILES=1`
- `RAILS_MASTER_KEY`: set manually from the Rails credentials master key.
- `SECRET_KEY_BASE`: generated by Render.

Do not commit `config/master.key` or any secret value.

## Admin Handoff

Andy needs to complete these steps in Render:

1. Create or sign in to a Render account.
2. Create a new Blueprint instance from the GitHub repository.
3. Select this branch once the deployment PR is merged, or select the PR branch
   for a preview deployment.
4. Confirm Render detects `render.yaml`.
5. Set `RAILS_MASTER_KEY` in the `andyportfolio-web` service environment.
6. Create the blueprint resources.
7. Trigger the first deploy if Render does not start it automatically.
8. Open the generated Render service URL and confirm `/` returns `200`.

The Rails root route points to `blogs#index`, so `/` is the deploy entrypoint
and Render health check path.
